# Phase 2+: バックグラウンド誘導アーキテクチャ

## 目的と安全境界

実YouTubeアプリを前面にしたまま、ARCore VIOとマーカー基準の保存経路で矢印誘導する。正しい前進は表示を回復し、停滞は徐々に暗くする。暗転70%まではYouTubeのタッチを利用でき、位置根拠が失われた時は古い方向を出さない。

精度目標は終点で数十cm。GPS等へのフォールバックは行わず、camera/Anchor tracking、経路妥当性、終点距離、cross-trackのいずれかが不足すれば安全側へ停止する。

## カメラ所有権と状態

`BackgroundTrackingService` は `IDLE / PREPARING / SEARCHING_MARKER / WAITING_FOR_VIEWING / GUIDING / TRACKING_LOST / ARRIVED / FAILED / STOPPING` を持つ。Activityはローカルbindのコールバックで状態を受け取り、`IDLE`以外ではPhase 1 ARCoreを作成・resumeしない。

視聴開始要求後、Phase 1でマーカーを認識してからPhase 1をcloseしサービスを開始する。Activityは画面に残り、サービスのARCore Sessionがresumeしてカメラ所有権を確立した時点で、選択済みのYouTubeアプリまたはブラウザを開く。サービス側のマーカー再認識完了は視聴先起動の条件にせず、YouTube表示後も背後で位置確立を続ける。Phase 1のマーカー待機中と権限設定中の開始要求はActivityの保存状態へ退避し、画面再生成後に復元する。サービス開始後の視聴先予約は、Intent開始が成功した場合だけ一度消費する。失敗時は予約を維持して1秒間隔で最大3回自動再試行し、一時的なバックグラウンド移行中はActivityが再び前面になってから再試行する。視聴先を開く前にActivityを終了した場合だけサービスを停止して予約を破棄し、YouTube起動後の通常誘導はMainActivityのBack操作では停止しない。通知やrecentsからActivityを開いても、サービスが`IDLE`になるまで第二のSessionは作らない。停止は固定待ち時間ではなく、owner threadのARCore/EGL解放後に届く`IDLE`通知で確認する。

ARCore Session、MarkerAnchor、EGLは専用owner threadだけが生成・更新・解放する。停止はAtomicBooleanで通知する。UI更新は最新値一件へ集約して約12.5Hzに抑え、ARCore updateは約30Hzを維持する。

## 位置合わせと追跡喪失

保存経路は開始時にマーカー座標の`GuidanceVector3`へ変換する。ただし、誘導計算はマーカー座標では行わない。マーカーが壁面に設置される場合、マーカーの+Yは壁から離れる水平方向、-Zは上方向となり、マーカー座標のX/Z平面は重力に対する床面ではない。

マーカー座標の保存経路は、マーカー軸の向きに依存しない3D検証を先に行う。点数は2点以上、全座標は有限、連続区間の3D累積長は0.20m以上でなければならない。マーカーロック後は、現在の`markerPoseInWorld`でworldへ変換した経路に対してのみ`GuidanceEngine`の重力水平X/Z検証を行う。

カメラの`Pose`は重力基準のARCore VIO world座標として扱い、毎フレームの有効な`markerPoseInWorld`で保存済みマーカー座標の経路点をworld座標へ変換する。現在位置とカメラ前方(-Z)もcamera world poseから取得し、`GuidanceEngine`の水平ナビゲーション、cross-track、終点距離はworld座標のX/Zで計算する。経路変換は、同じルートと姿勢値が完全一致するフレームだけ安全にキャッシュし、アンカーの姿勢更新を飛ばさない。

方向更新にはcameraとAnchorの両方の`TRACKING`が必要。非nullの過去poseは使わない。ロック前は`SEARCHING_MARKER`とし、初回ロックだけ8秒を上限とする。一度ロックした後の`PAUSED`は`TRACKING_LOST`とし、同じSessionとAnchorを保持したまま固定時間制限なしで復帰を待つ。喪失中は古い矢印を消し、暗転濃度・進行窓・到着判定を凍結する。cameraまたはAnchorが`STOPPED`になった場合だけ復帰不能として`FAILED`へ進み、Session/EGLを解放する。マーカーの再スキャンは要求しない。

## 経路、進行、到着

保存経路は3D累積長20cm以上を要求し、worldへ変換した後にも水平長20cm以上であることを`GuidanceEngine`で確認する。`GuidanceEngine`はworldの重力水平X/Z面で投影し、弧長、残距離、cross-track、終点までの水平直線距離を返す。高さの変化は到着判定に使わない。

到着候補は終点0.6m以内かつcross-track 0.75m以内。1秒連続して成立した時だけラッチする。誘導開始時に選んだモードにより、到着後は暗転を即時解除して650ms後に停止するか、到着時点の暗転を2.5秒かけて滑らかに解除してから停止する。いずれも最後にカメラとオーバーレイを解放する。

`FadeController`は低域通過した正味前進を0.5秒窓で評価し、8cmの報酬をフレームレートに依存せず蓄積する。ミリメートル級の負の揺れは窓内で相殺するが、定常振動、実質的な逆行、オフルート、追跡喪失、不自然な速度ジャンプは報酬にしない。開始3秒・最終進行から2秒の猶予後に、1〜60秒の範囲で設定した時間をかけて0%から100%へ暗転する。有効前進中は最大毎秒0.45で回復する。

owner failureはSession/EGLを直ちに解放して`FAILED`から`IDLE`へ進むが、正確な終了理由をサービスのterminal statusに保持する。Activityは`IDLE`で理由を消さず、次回開始または明示的なacknowledgeまで表示する。

## オーバーレイとタッチ

矢印と黒膜は一枚の全画面`TYPE_APPLICATION_OVERLAY`に統合し、`FLAG_NOT_TOUCHABLE`を付ける。要求暗転が0〜70%の間はwindow alphaを0.70に保ち、内部黒Viewのalphaで見た目を調整する。70%を超えたら内部黒Viewを1.0に固定し、window alphaを要求暗転とともに1.0まで上げて100%暗転へ到達する。

Android 12のuntrusted-touch判定はwindow alphaを使い、同一UIDの複数windowは`1-(1-a)(1-b)`で合成される。既定上限0.8以下ではYouTubeへタッチを通せるが、それを超える終盤はタッチがブロックされる。100%暗転と完全なタッチ透過はOSのセキュリティ上両立しない。通知の表示切替と停止を常時残す。Phase 2aデバッグoverlayはwindow alpha 0.70のままとする。

## 視聴開始導線

targetSdk 34のcamera foreground serviceはwhile-in-use制約を受ける。このため視聴中のYouTubeからカメラ画面へ自動で戻す方式は使わない。ユーザーがKunekune Escapeを開き「位置合わせして視聴開始」を選び、Phase 1でマーカーを認識した後に可視Activityからcamera FGSを開始する。サービスのARCore Sessionがresumeした時点で、ActivityがYouTubeアプリまたは既定ブラウザのYouTube URLを開く。視聴開始時点でカメラサービスは稼働済みだが、サービス固有のARCore座標系でのマーカー再確立は背後で継続するため、切替直後もしばらく端末をマーカーへ向けた状態を保つ必要がある。

視聴先は設定で切り替え、未設定時はブラウザ版を既定とする。YouTubeアプリ指定時は`com.google.android.youtube`へURL Intentを送り、未インストールならブラウザへフォールバックする。ブラウザ指定時は既定ブラウザ、次いでインストール済みブラウザのパッケージを解決して明示指定し、YouTube App Linksに横取りされないようにする。

視聴先Intentの開始に成功した実パッケージ名をサービスへ返し、`UsageStatsManager`でそのパッケージが前面にある時間だけを連続視聴として数える。別パッケージへの移動、画面消灯、キーロック、利用状況データ欠損では0へ戻す。1秒未満で対象へ戻った場合も、間に発生したforeground・screen・keyguardイベントを中断として保持する。閾値は1〜120分を1分単位、既定30分とする。閾値前もcamera FGSとARCoreの位置確立は継続するが、オーバーレイは透明・無表示の`WAITING_FOR_VIEWING`とする。閾値到達後は介入をラッチし、その後の一時的なアプリ切替で解除しない。利用状況への特別アクセスは開始前に確認し、未許可ならAndroid設定へ案内する。

UsageStatsの読み取りはARCore Session owner threadでは行わない。視聴先起動成功後にだけ専用の単一スレッドを開始し、初回は直近5分、以後は前回の排他的終了時刻からの差分イベントだけを1秒間隔で読む。完成したimmutable観測を世代番号付きでAR側へ渡し、1観測につき1回だけ単調時刻を加算する。AR側が一時停止して複数観測が溜まった場合も、別パッケージ・画面・ロック・データ欠損・権限取消の安全フラグは失わず統合する。対象Activityの`PAUSED`後に後続`RESUMED`がまだ届かない区間は、累積時間を維持したまま観測基準時刻だけを破棄し、曖昧な時間を加算しない。10秒間データが届かない、または古くなった場合は安全停止する。

この方式は常時監視やブート時起動を行わず、可視Activityから開始したcamera FGSの寿命内だけで動作する。したがってtargetSdk 34のwhile-in-use制約を回避せず順守できる。ブラウザはパッケージ単位の判定なので、同じブラウザ内のURL・タブ変更は識別しない。

## 実機で確認する項目

- YouTubeの再生、スクロール、戻る操作が70%以下で通り、80%超では意図通り遮断されること
- Phase 1のマーカー認識前にはYouTubeが開かれず、サービスのカメラ準備完了後に選択した視聴先が一度だけ開くこと
- 15/30/60Hz相当の低速歩行、停止、逆行、横外れで暗転/回復が意図通りであること
- 初回位置確立は8秒で安全停止し、確立後のcamera/Anchor `PAUSED`では古い矢印を出さず、時間制限やマーカー再スキャンなしで自動復帰すること。`STOPPED`では安全停止すること
- 視聴先以外のアプリ、画面消灯、キーロックで連続時間がリセットされ、設定閾値に達するまで矢印・暗転が表示されないこと
- 高さを変えても終点の水平誤差が数十cmに収まり、横に外れた位置で誤到着しないこと
- 通知停止、表示切替、recents再入場、到着後停止でカメラが確実にPhase 1へ戻ること
