# Kunekune Escape パッチノート

今後の変更はこのファイルの先頭へ追記する。日付は実装日、検証欄には実際に完了した確認だけを書く。

## Unreleased — 視聴中断・到着後介入の修正（2026-07-23）

### 変更
- 暗転密度100%で背後のコンテンツが完全に見えなくなるよう、到着・追跡ロスト表示でも黒い遮蔽を維持するようにした。
- 連続視聴による介入成立後、YouTubeアプリまたは対象ブラウザを閉じたり別アプリへ移動したりすると誘導と暗転を非表示にし、対象へ戻ると待ち時間なしで再表示するようにした。
- 確立済みのトラッキングが失われた場合は、再スキャンを要求せず復帰を待ちながら最大遮蔽を適用し、矢印の位置へ「壁や床から離してください」と表示するようにした。
- 「フェードで終了」は、到着時点の暗さから1〜120分で完全遮蔽まで徐々に濃くし、その後も対象コンテンツが前面の間は遮蔽を維持するようにした。
- 「すぐに解除」は目的地内で暗転を即時解除し、目的地から離れた場合は別設定の1〜120分で完全遮蔽まで再暗転するようにした。目的地へ戻ると再び即時解除する。
- 到着後暗転と目的地離脱後暗転のタイマーは、YouTubeアプリまたは対象ブラウザが前面にない間は一時停止する。

### 検証
- ホスト側ユニットテスト67件、Debug APKビルド、Lint成功。
- Pixel 6aへの上書きインストール、MainActivity起動、プロセス生存、起動直後に致命的エラーがないことを確認。
- 連続視聴・前面復帰・床／壁復帰・到着後2モードの実機操作確認は未実施。

## Unreleased — Phase 2d 改訂（2026-07-22）

### 追加
- 到着時の挙動を、誘導を開始するたびに「すぐ解除」と「フェード終了」から選択するようにした。
- フェード終了は、到着時点の暗転を2.5秒かけて滑らかに解除してから誘導サービスを終了する。
- 停滞判定後から100%暗転までの時間を1〜60秒の範囲で1秒単位に調整可能にした。初期値は30秒。
- YouTubeの連続視聴開始から介入までを1〜120分の範囲で1分単位に調整可能にした。初期値は30分。
- 視聴先をYouTubeアプリと既定ブラウザ版から選択可能にした。未設定時の既定値はブラウザ版とする。
- 「位置合わせして視聴開始」からマーカーを先に認識し、バックグラウンドカメラの準備完了後に選択したYouTubeを自動で開く導線を追加した。
- カメラサービスが既に稼働している視聴セッション内で、実際に開いたYouTubeアプリまたはブラウザのパッケージが前面にある時間だけを計測し、設定時間に達すると矢印と暗転介入を表示するようにした。別アプリ、画面消灯、画面ロック、利用状況データ欠損では連続時間をリセットする。
- マーカー待機中・権限設定中の開始要求を画面再生成後に復元し、サービス開始後の視聴先予約もサービス側で保持することで、画面回転や一時的なバックグラウンド移行でも失わず、前面復帰後に一度だけ起動するようにした。
- YouTube起動後にMainActivityへ戻ってBackを押しても通常誘導を停止せず、視聴先を開く前の仕掛け途中だけ安全に取り消すようにした。

### 変更
- 最大約70%だった暗転を100%まで到達するよう変更した。暗転70%まではwindow alpha 0.70を維持し、それ以降はwindow alphaを暗転密度とともに1.0まで上げる。
- 旧UsageStats試作のような常時監視や、検知後にカメラを起動する方式は使わない。可視Activityから開始済みのcamera FGS内だけで連続視聴を判定することで、「アプリ起動→マーカー認識→YouTube」の既存導線を維持した。
- 連続視聴の閾値に達するまではオーバーレイを透明・無表示にし、介入開始を事前告知しない。
- 未使用の「2A: 裏で追跡テスト」ボタンを画面から削除した。

### 修正
- YouTube起動条件がサービス側での二度目のマーカー認識完了になっており、セッション切替時に再認識できないと自動起動しない問題を修正した。前面でマーカーを認識した後は、サービスのARCoreカメラが再開した時点で視聴先を開く。
- 視聴先Intentの開始に失敗しても起動予約を消費せず、前面復帰後に再試行できるようにした。正常に開始できた場合だけ予約を完了する。
- 視聴先Intentの一時的な失敗は1秒間隔で最大3回自動再試行する。
- 既定ブラウザから各インストール済みブラウザまで順番に明示起動し、1件の起動失敗で停止せず、ブラウザ版指定がYouTubeアプリへ横取りされないようにした。
- サービス側で初回マーカーを8秒以内に再確立できない場合は、安全停止してカメラとオーバーレイを解放するようにした。
- 一度マーカー位置を確立した後のARCore `PAUSED`では、同じSessionとAnchorを保持したまま無期限に自動復帰を待つようにした。姿勢を信頼できない間は古い矢印を消し、`STOPPED`だけを復帰不能として安全停止する。
- 連続視聴カウンターが中断直後の最初の観測間隔を誤加算しないよう修正した。
- 利用状況イベントをARCoreの更新スレッドで24時間分ずつ再走査していた処理を廃止した。専用スレッドで初回5分、以後は差分だけを1秒間隔で読み、AR側は完成済みの観測だけを1回ずつ消費する。
- 同じブラウザ内のActivity切替、1秒未満の別アプリ往復、短い画面消灯・ロック、データ欠損を連続視聴として誤加算しないよう、イベント中断情報を次の観測まで保持するようにした。
- 対象Activityの`PAUSED`と次Activityの`RESUMED`が別の読取区間に分かれた場合は、連続時間を消さずに時計だけ一時停止して次イベントで同一／別パッケージを確定するようにした。閾値直前の切替でも誤発動せず、同一アプリ内遷移で最初から数え直さない。
- 利用状況アクセスとオーバーレイ権限を拒否して戻った時に設定画面が自動で再表示され続ける／再度開けなくなる問題を修正した。戻った直後は説明を表示し、開始操作をやり直した時だけ再度設定を開く。
- 既存サービスを停止してから新しい誘導を開始する経路で、保留中の開始要求と到着モードが消える問題を修正した。
- 旧サービスが`IDLE`を通知した直後に新サービスを開始し、旧`stopSelf()`が新しい開始まで止める競合を修正した。`STOPPING`でActivityを先にunbindし、`onDestroy`の資源解放後に静的状態が`IDLE`になったことを非同期確認してから、必要な新開始またはPhase 1復帰を行う。STOPPING中の再bindも禁止した。

### 制約
- Android 12以降ではオーバーレイの不透明度が0.8を超えると、下のYouTubeへのタッチがセキュリティ上ブロックされる。100%暗転との両立はできないため、終盤の暗転は表示だけでなく操作も遮断する。
- 現在の位置合わせ画像はARCore用マーカーでありQRコードではない。QRへ置き換える場合は、同じ画像をARCoreの位置基準にもして印刷物を差し替える必要がある。
- ブラウザ版は前面ブラウザのパッケージ単位で判定するため、同じブラウザ内でYouTube以外のURLや別タブへ移ったことまでは識別できない。

### 検証
- ホスト側ユニットテスト63件、Debug APKビルド、Lint成功。
- 実機が未接続のため、今回のAPK再インストールと連続視聴・追跡復帰・到着モードの実機確認は未実施。

## 撤回済み試作 — 常時監視型UsageStats自動検知（2026-07-22）

- YouTubeの連続前面利用検知、画面ロック・再起動境界処理、常駐監視を試作した。
- Android 14のカメラ制約を守るには検知後に可視Activityへ戻す必要があり、「いつの間にか介入が存在する」体験にならないため同日撤回した。この常時監視・検知後カメラ起動方式はリリース対象に含めず、代わりに開始済みcamera FGS内のセッション限定検知を採用した。

## Phase 2 品質再構築（2026-07-22）

### 改善
- マーカー座標の経路を毎フレームVIOワールド座標へ変換し、壁面マーカーでも重力水平面上の誘導が成立するよう修正した。
- 保存経路の3D検証と、変換後経路の水平検証を分離した。
- 矢印と暗転膜を単一のタッチ透過オーバーレイへ統合した。
- 停滞判定を瞬間差分から0.5秒の平滑化済み正味前進へ変更し、揺れ・逆行・経路外移動・不自然な位置ジャンプを報酬から除外した。
- マーカーとカメラの両方が追跡中のフレームだけ位置根拠を更新するようにした。
- 到着を終点距離、経路幅、1秒継続の組み合わせで確定するようにした。
- ARCore/EGL/Anchorを所有スレッドで一括解放し、終了理由をActivity復帰後まで保持するようにした。
- 上記の幾何、フェード、安全判定、終了理由にユニットテストを追加した。

### 検証
- ホスト側ユニットテスト成功。
- Debug APKビルド成功。
- Pixel 3aへ導入し、通常導線の正常動作を確認済み。
